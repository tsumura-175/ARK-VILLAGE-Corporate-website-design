# ARK LEAGUE デザインガイドライン

## 1. 目的

本ガイドラインは、ARK LEAGUEのコーポレートサイトにおけるデザイン判断を統一するための基準です。ページやコンポーネントを追加する際は、既存画面を部分的に模倣するのではなく、本書の原則と `assets/css/tokens.css` を基準に設計してください。

具体的なコンポーネント構造、状態、組み合わせ方は `DESIGN_SYSTEM.md` を参照してください。

## 2. ブランドコンセプト

### キーワード

- **Living Culture. Shaping the Future.**
- ストリートスポーツ
- コンクリート
- 現場感
- 都市性
- 信頼感
- 洗練

### 目指す印象

ストリートスポーツの力強さと、企業サイトとして必要な信頼感を両立します。荒々しいストリート表現だけに寄せず、余白、整列、タイポグラフィによって上質さをつくります。

### 避ける印象

- 派手なグラデーションや過剰な装飾
- ゲームサイトのような演出
- 丸いカードを多用した一般的なSaaS風デザイン
- ポップすぎる配色
- 写真を隠すほど強い背景パネル
- 企業情報が読みづらくなる過度な実験表現

## 3. カラー

色は必ず `assets/css/tokens.css` のカスタムプロパティを使用します。コンポーネント内へHEXやRGBを直接記述しません。

| 用途 | トークン | 方針 |
| --- | --- | --- |
| 基本背景 | `--color-paper` | 温かみのあるオフホワイト |
| 補助背景 | `--color-paper-2` / `--color-paper-3` | セクションの階層化 |
| 基本文字 | `--color-ink` | 真っ黒ではないコンクリート調の黒 |
| 補助文字 | `--color-muted` | 説明文、日付、補助情報 |
| 暗色面の文字 | `--color-on-dark` | KV、フッター、暗色セクション |
| アクセント | `--color-accent` | 斜線、進捗線、重要な状態 |
| 境界線 | `--color-rule` / `--color-rule-2` | 情報を静かに区切る |
| フォーカス | `--color-focus` | キーボード操作時の可視化 |

赤はブランドのアクセントとして限定的に使用します。大面積の背景には使わず、線、進捗、ホバー、重要な状態に絞ります。

## 4. タイポグラフィ

### 書体

- 英字見出し・数字：`--font-display`（Antonio）
- 日本語本文・UI：`--font-body`（Noto Sans JP）

### 原則

- 大きな英字と読みやすい日本語の対比をつくる
- 日本語本文は可読性を優先し、極端に詰めない
- 見出しは短く、本文へ役割を持ち込まない
- 英字見出しは原則として大文字
- 同じ階層では文字サイズ、太さ、行間を統一する
- 文字サイズは `--text-*` トークンを使用する
- セクション見出しの上端位置は、SPでは `--space-3xl`、PC・タブレットでは `--space-4xl` を基準に揃える
- 英字見出しの行間は `1` とし、本文用の行間指定を継承させない

## 5. レイアウトと余白

- 最大ページ幅：`--page-max`
- 本文・主要コンテンツ幅：`--content-max`
- 左右余白：`--page-gutter`
- 余白は `--space-*` のスケールから選ぶ
- セクション間は広く、コンポーネント内部は情報関係に応じて詰める
- PCでは非対称レイアウトを許容するが、整列軸を必ず持たせる
- モバイルでは原則1カラムとし、読み順を優先する

新しい余白値をその場で作らず、既存トークンで表現できない理由がある場合のみ `assets/css/tokens.css` へ追加します。

## 6. 写真

### 選定

- BMX、スケートボード、パーク、イベント会場など事業との関係が明確な写真
- コンクリートや都市環境の質感が伝わる写真
- 被写体の動きや現場の空気が感じられる写真
- ロゴや文字を重ねる場合でも、主要被写体が見切れない構図

### 表示

- KVは画面いっぱいに使用する
- 切り抜きは `object-fit: cover` を基本とする
- 画像ごとに `object-position` を調整し、BMXや人物を優先する
- カード画像のアスペクト比は同一グループ内で統一する
- 不要なダミー画像や空白の画像枠を残さない

## 7. 主要コンポーネント

### ヘッダー

- 初期状態はKVと一体化した透明な表示
- 初期状態に硬い水平線や帯状背景を置かない
- スクロール量に連動し、背景、影、ぼかしを徐々に表示する
- 切り替え前後で幅・高さ・内側余白を急変させない
- ナビゲーション項目数はワイヤーフレームに合わせる

### KV

- 画像を全面表示する
- メインコピーは中央配置を基本とする
- 社名は白文字と控えめな文字影で視認性を確保する
- 画像はゆっくりズームする
- 切り替え時は、退出画像のズームを維持したままフェードアウトする
- ゲージと画像切り替えの時間は同期させる
- マウスホバーでは自動再生を停止しない
- 初回表示時は、メインコピーを横方向の短いリビールで表示する。文字単位の過度な演出は避け、ロゴ・英字コピー・日本語コピーの順に情報を示す
- 横方向のリビール用マスクは上下に余裕を持たせ、小文字のディセンダー（`g`、`p`、`y` など）を切らない
- `prefers-reduced-motion` ではKVの入場モーションを省略し、すべてのテキストを即時表示する

### 下層ページヒーロー

- 画面の約3分の2を占めるタイトル専用領域とする
- 英字タイトル、日本語タイトル、赤い斜線、下端のラインを共通要素とする
- 説明文、CTA、写真は原則として置かず、ページ名の認知に集中させる
- ページごとの差は文言とアクセントの配置に限定し、寸法と動きは統一する
- 初回表示では横方向の短いリビールを使い、常時動く装飾は置かない

### セクションタイトル

- 左上の赤い斜線
- 大きな英字タイトル
- 小さな日本語タイトル
- 説明文を含む4要素を同じタイトルコンポーネント内で管理する
- 英字見出し・日本語見出しのサイズ、行間、赤い斜線との距離は全セクションで統一する
- 説明文は日本語見出しの直下へ配置し、PC・タブレット・スマートフォンで「英字見出し→日本語見出し→説明文」の順序を維持する
- 見出し・説明文から主コンテンツまでの余白は `--space-2xl` を基準にする
- 下層ページの各コンテンツでも同じタイトル部品を使い、画面幅にかかわらずタイトルを左上、主コンテンツをその下へ配置する
- NEWSも他セクションと同じ見出し下余白（`--space-2xl`）を確保する
- NEWSはタイトルブロックをセクション上部に配置し、5件の一覧を中央幅へ揃える。「ニュース一覧を見る」は一覧の直下に置く
- COMPANYは見出し・日本語見出し・会社説明文を写真の外側上部へ配置する。写真はその直下に置き、補足文と導線だけを写真右下へ重ねる
- COMPANYの写真は、建物を左、補足文を置ける空の領域を右に残すよう表示位置を調整する

### ボタン・リンク

- 主要CTAはピル型を基本とする
- 補助リンクはテキストと円形矢印を組み合わせる
- 矢印の垂直位置を文字と揃える
- 1つのホバーに複数の派手な動きを重ねない
- キーボードフォーカスを必ず表示する

## 8. モーション

| 用途 | 基準 |
| --- | --- |
| UIホバー | `--dur-short` |
| 通常の表示変化 | `--dur-long` |
| ヘッダー | `--dur-nav` またはスクロール連動 |
| KVフェード | `--dur-slide` |
| KVズーム | `--dur-zoom` |
| KV切り替え間隔 | `--slider-delay` |

モーションは情報の切り替わりを理解しやすくするために使用します。装飾だけを目的とした連続アニメーションは追加しません。`prefers-reduced-motion` では主要なアニメーションを停止または短縮します。

## 9. レスポンシブ

最低確認幅は以下です。

- 320px
- 375px
- 768px
- 1280px
- 1440px

確認事項：

- 横スクロールが発生しない
- CTAとメニュー項目が不自然に改行されない
- KVの主要被写体が見切れすぎない
- 見出しが画面幅を超えない
- タップ領域が最低44pxある
- PCとモバイルで情報の優先順位が変わっていない

## 10. アクセシビリティ

- 文字と背景のコントラストを確保する
- 装飾画像は `alt=""`、意味のある画像は内容を説明する
- 見出しレベルを順序どおりに使用する
- フォームには視覚的なラベルを付ける
- エラーは色だけで伝えず、文章でも表示する
- モーダルや認証画面はキーボード操作を考慮する
- 動きの軽減設定へ対応する

## 11. 更新時の確認

1. 本書のブランド原則に合っているか確認する
2. `assets/css/tokens.css` の既存トークンで表現する
3. 同種コンポーネントとサイズ・余白・動きを揃える
4. PCとモバイルで確認する
5. コントラスト、フォーカス、画像代替文を確認する
6. 新しい判断が今後も繰り返される場合は本書へ追記する

# ARK LEAGUE デザインガイドライン

## 1. 目的

本ガイドラインは、ARK LEAGUEのコーポレートサイトにおけるデザイン判断を統一するための基準です。ページやコンポーネントを追加する際は、既存画面を部分的に模倣するのではなく、本書の原則と `assets/css/tokens.css` を基準に設計してください。

具体的なコンポーネント構造、状態、組み合わせ方は `DESIGN_SYSTEM.md`、実物の見本は `components.html` を参照してください。本書は2026-11-07時点の実装に合わせたデザイン原則です。

## 2. ブランドコンセプト

### 目指す印象

ストリートスポーツの力強さと、企業サイトとして必要な信頼感を両立します。荒々しいストリート表現だけに寄せず、余白、整列、タイポグラフィによって上質さをつくります。

- 企業情報が読みづらくなる過度な実験表現

## 3. カラー

色は必ず `assets/css/tokens.css` のカスタムプロパティを使用します。コンポーネント内へHEXやRGBを直接記述しません。

| 用途 | トークン | 方針 |
| --- | --- | --- |
| 基本背景 | `--color-paper` | 温かみのあるオフホワイト |
| 補助背景 | `--color-paper-2` / `--color-paper-3` | セクションの階層化 |
| 基本文字 | `--color-ink` | 真っ黒ではないコンクリート調の黒 |
| 補助文字 | `--color-muted` | 通常の説明文、日付、補助情報 |
| セクション見出し・指定本文 | `--color-section-title` | #5e5652。企業理念の本文・交通案内の説明にも使用 |
| 暗色面の文字 | `--color-on-dark` | KV、フッター、暗色セクション |
| アクセント | `--color-accent` | 斜線、進捗線、重要な状態 |
| 境界線 | `--color-rule` / `--color-rule-2` | 情報を静かに区切る |
| フォーカス | `--color-focus` | キーボード操作時の可視化 |

赤はブランドのアクセントとして限定的に使用します。大面積の背景には使わず、線、進捗、ホバー、重要な状態に絞ります。

## 4. タイポグラフィ

### 書体

- 日本語の見出し・本文・UI、通常の情報表示、NEWS・WORKSのページネーション数字：Noto Sans JP。
- フォームのステップ番号、英字の大見出し・コンセプト文・装飾番号・工程番号・スケジュールの年表示・FAQのQ/A、および今回維持する英字ラベル：Antonio。
- 対象クラスと維持するラベルの範囲は `DESIGN_SYSTEM.md` 第2章、ページ送りは第16章を正本とする。書体ルールを理由に指定外のCSSや文字値を一括変更しない。

### 見出し・本文・ラベルの原則

- 文字の役割は、大見出し・中見出し・小見出し・リード・本文・強調本文・項目ラベル・補足に分ける。数値・使用条件・既存クラスとの対応は `DESIGN_SYSTEM.md` 第2章・第13章を正本とする。
- HTMLの見出し階層は内容の構造で決める。リードは紹介やメッセージの文章であり、サイズだけを理由に見出しと混同しない。
- 大見出しは現行の英字＋日本語＋斜線を一組として使い、幅に応じた自動縦積みを維持する。長い施設名や職種名は実際の採用カードで確認し、見本だけの将来案を常設しない。
- 18pxの強調本文は重要なお知らせと主要条件の要約に使う。通常情報表の項目名・値はその役割を分け、全ての値を一律に強調しない。
- 小見出し直後の上罫線までの距離と、部品内部のpadding・工程内の列間は別用途として管理する。赤い縦線を持たない記事本文・ポリシーの小見出しも、標準の小見出し仕様を使う。
- デザイン見本には短い見本名・状態名と自然なサンプル文章を置く。実装方法・ファイル名・使用先はMarkdownへ記載する。見本名とサンプル枠の配置は `docs/components.css` へ分離し、見本整理のためにサイトのリードを小さくしない。
- TOPのKV、ナビ、ボタン等は現行の用途別仕様を維持する。番号付き工程はPC/SPとも番号を左、見出し・本文を右へ揃え、PCの3列は維持する。工程とNEWSカテゴリの詳細はデザインシステムを参照する。新しい部品は必要になった時点で設計する。

## 5. レイアウトと余白

- 最大ページ幅：`--page-max`
- 本文・主要コンテンツ幅：`--content-max`
- 左右余白：`--page-gutter`
- 余白は `--space-*` のスケールから選ぶ
- セクション間は広く、コンポーネント内部は情報関係に応じて詰める
- PCでは非対称レイアウトを許容するが、整列軸を必ず持たせる
- モバイルでは文章・写真の読み順を優先する。アイコン一覧・取引先名一覧は1列、ページ内メニューは2列。TOP飲食出店の対になるボタンは共通サイズを保ち、収まる幅では横並び、収まらなければ同幅の縦並びにする。フォームの既存2列操作群は別用途として維持する
- 補助背景は斜面を繰り返さず、薄い構造グリッドや濃度差によって都市・施設の印象を補う
- 説明主体の本文は標準幅で右側に余白を残す。写真・図面・地図・一覧・表・工程はページ本文幅まで広げ、段落の行長だけ必要に応じて抑える。すべてを同じ幅へ揃えず、情報の用途で使い分ける。共通Modifierの使い方は `DESIGN_SYSTEM.md` に従う

新しい余白値をその場で作らず、既存トークンで表現できない理由がある場合のみ `assets/css/tokens.css` へ追加します。

## 6. 写真

### 選定

- BMX、スケートボード、パーク、イベント会場など事業との関係が明確な写真
- コンクリートや都市環境の質感が伝わる写真
- 被写体の動きや現場の空気が感じられる写真
- ロゴや文字を重ねる場合でも、主要被写体が見切れない構図

### 表示

- KVは画面いっぱいに使用する
- 写真は `object-fit: cover` を基本とする。ロゴ・図面は縦横比を保ち、`contain` または自然な高さで全体を表示する
- 画像ごとに `object-position` を調整し、BMXや人物を優先する
- カード画像のアスペクト比は同一グループ内で統一する
- WORKSの31実績はすべて指定実写真を使う。クライアント指定で仮画像を残している箇所は、実際の施設・区画・イベント写真として扱わない
- 取引先一覧はロゴを使わず、確定した14名称を読めるテキストで掲載する。法人は指定の正式商号を使い、自治体名・ブランド名は指定表記を維持する。名称にリンクを付けず、共通の文字色・余白・罫線で整える。SP1列・タブレット2列・PC3列とし、「株式会社ディー・エヌ・エー」「株式会社ムラサキスポーツ」など長い名称も不自然に分割しない
- TOP飲食出店の紹介写真には説明文や可読性用の暗いグラデーションを重ねない。上部見出しと画像の構図を保ち、右下の完成イメージ表記を残す。
- 写真のクレジット指定を保持する。完成イメージ・撮影者名は共通 `.media-caption` で画像右下に置く

## 7. 主要コンポーネント

### ヘッダー

- 初期状態はKVと一体化した透明な表示
- 初期状態に硬い水平線や帯状背景を置かない
- スクロール量に連動し、背景、影、ぼかしを徐々に表示する
- 切り替え前後で幅・高さ・内側余白を急変させない
- ナビゲーション項目数はワイヤーフレームに合わせる

### KV

- 画像を全面表示する
- メインコピーは中央配置を基本とする
- 社名は白文字と控えめな文字影で視認性を確保する
- 画像はゆっくりズームする
- 切り替え時は、退出画像のズームを維持したままフェードアウトする
- ゲージと画像切り替えの時間は同期させる
- マウスホバーでは自動再生を停止しない
- 初回表示時は、メインコピーを横方向の短いリビールで表示する。文字単位の過度な演出は避け、ロゴ・英字コピー・日本語コピーの順に情報を示す
- 横方向のリビール用マスクは上下に余裕を持たせ、小文字のディセンダー（`g`、`p`、`y` など）を切らない
- `prefers-reduced-motion` ではKVの入場モーションを省略し、すべてのテキストを即時表示する

### 下層ページヒーロー

- 画面の約3分の2を占めるタイトル専用領域とする
- 英字タイトル、日本語タイトル、赤い斜線、下端のラインを共通要素とする
- ページ名の英字・日本語を中心にし、説明文やCTAは置かない。写真付きの下層KVは `.page-hero--image` で写真と共通ベールを使用する。NEWS一覧・記事詳細は例外として、写真なしの `.page-hero` を使用する。共通部品見本も写真なしで構造を確認できる
- 寸法・文字サイズ・動きは共通化し、背景写真と表示位置だけ主題に合わせる。WORKSはPC/SP別の専用WebPでRed Bullの文字を残す。写真対応は `WORKS_ASSETS.md` を参照する
- 初回表示では横方向の短いリビールを使い、常時動く装飾は置かない

### セクションタイトル

- 左上の赤い斜線
- 大きな英字タイトル
- 日本語タイトル（PC32px／SP24px）
- 説明文が必要な場合だけ4番目の要素として同じタイトルコンポーネント内に置く
- 英字見出し・日本語見出しのサイズ、行間、赤い斜線との距離は全セクションで統一する
- 英字見出しと日本語見出しは、親見出し領域の実際の空き幅に収まる場合は横並びにし、収まらない場合は縦積みにする。英字が複数行のときは日本語を英字の最終行の右に揃える。説明文は両方の下へ配置し、DOMの読み順は英字→日本語→説明文とする
- 見出し・説明文から後続の主コンテンツ部品までの余白は `--type-section-after`（PC64px／SP40px）で一度だけ確保する
- 下層ページの各コンテンツでも同じタイトル部品を使い、画面幅にかかわらずタイトルを左上、主コンテンツをその下へ配置する
- NEWSも他セクションと同じ見出し下余白（`--type-section-after`）を確保する
- NEWSはタイトルブロックをセクション上部に配置し、一覧の左端を英字タイトルに揃え、左右余白を均等にする。「お知らせ一覧を見る」は一覧の直下に置く
- COMPANYは見出し・日本語見出し・会社説明文を写真の外側上部へ配置する。写真はその直下に置き、補足文と導線だけを写真右下へ重ねる
- COMPANYの写真は、建物を左、補足文を置ける空の領域を右に残すよう表示位置を調整する

### ボタン・リンク

- TOPの飲食出店FAQは、日本語の項目ラベルで移動先を説明し、大きい英字FAQと既存矢印を組み合わせる。PCは横並び、SPは日本語と英字を上下に置き、長い日本語を縮小しない。具体値は `DESIGN_SYSTEM.md` 第19章を参照する。

- TOPの募集告知はNEWS見出しの直下に置き、背景を周囲と分けず赤い1pxの四辺枠で区切る。告知文は小見出し、操作は共通の黒い「募集概要を見る」ボタンに集約する。写真・日付・専用背景面を追加しない。仕様と管理は `DESIGN_SYSTEM.md` 第18章を参照する。

- 主要CTAはピル型を基本とする
- 補助リンクはテキストと円形矢印を組み合わせる
- 矢印の垂直位置を文字と揃える
- 1つのホバーに複数の派手な動きを重ねない
- キーボードフォーカスを必ず表示する
- ページ内移動は丸囲み下矢印、PDFは下線付きのダウンロードSVGで区別する
- TOP飲食出店の「詳細を見る／応募フォームへ」は、文字・丸矢印・内余白を縮めず、利用可能幅で横並び／同幅の縦並びを切り替える。フォーム用の対になる操作とはルールを分け、飲食出店ページの応募・PDFとその下の補助リンクは既存配置を維持する

## 8. モーション

| 用途 | 基準 |
| --- | --- |
| UIホバー | `--dur-short` |
| 通常の表示変化 | `--dur-long` |
| ヘッダー | `--dur-nav` またはスクロール連動 |
| KVフェード | `--dur-slide` |
| KVズーム | `--dur-zoom` |
| KV切り替え間隔 | `--slider-delay` |

モーションは情報の切り替わりを理解しやすくするために使用します。装飾だけを目的とした連続アニメーションは追加しません。`prefers-reduced-motion` では主要なアニメーションを停止または短縮します。

## 9. レスポンシブ

最低確認幅は以下です。

- 320px
- 375px
- 768px
- 1280px
- 1440px

確認事項：

- 横スクロールが発生しない
- CTAとメニュー項目が不自然に改行されない
- KVの主要被写体が見切れすぎない
- 見出しが画面幅を超えない
- タップ領域が最低44pxある
- PCとモバイルで情報の優先順位が変わっていない

## 10. アクセシビリティ

- 文字と背景のコントラストを確保する
- 装飾画像は `alt=""`、意味のある画像は内容を説明する
- 見出しレベルを順序どおりに使用する
- フォームには視覚的なラベルを付ける
- エラーは色だけで伝えず、文章でも表示する
- モーダルや認証画面はキーボード操作を考慮する
- 動きの軽減設定へ対応する

## 11. 更新時の確認

1. 本書のブランド原則に合っているか確認する
2. `assets/css/tokens.css` の既存トークンで表現する
3. 同種コンポーネントとサイズ・余白・動きを揃える
4. PCとモバイルで確認する
5. コントラスト、フォーカス、画像代替文を確認する
6. 新しい判断が今後も繰り返される場合は本書へ追記する
